Trust & Security

This page describes the trust and security principles applied to the Alle's ClinX Knowledge publishing experience, including its static architecture, browser-side search, offline caching, external links, and correction process.

It does not claim a certification, penetration-test result, or security guarantee. Separate Alle's ClinX commercial systems may use different infrastructure and controls.
01Static publishing architecture

Knowledge is published as static site content. Reading an article does not require a Knowledge account, server-side profile, shopping cart, or payment flow. This reduces the amount of application state the Knowledge front end needs to handle.

02Transport and hosting

The live GitHub Pages site is delivered over HTTPS. Hosting, network delivery, and platform-level protections are provided in part by GitHub and related infrastructure, subject to their own security controls and terms.

03Search and local processing

Knowledge search loads a static index and performs ranking in the browser. The site does not need a dedicated Alle's ClinX search server to receive each search phrase.

This design limits the number of moving parts involved in ordinary Knowledge discovery.

04Offline cache

A service worker can cache site assets and previously visited content for offline access. Cached content may remain on a device until the browser evicts it or the user clears site data.

Users working on shared devices should clear browser site data if local persistence is not appropriate for their environment.

05External services

Knowledge links may open GitHub, allesclinx.com, email, documents, or other services. Security and data handling on those destinations depend on the service that receives the request. Check the destination before submitting credentials or sensitive information.

06AI-assisted information

AI-assisted answers should be checked against current official source documents when the decision affects safety, compliance, product handling, or another consequential outcome. The AI & Data Use page describes this source-first approach in more detail.

07Corrections and responsible reporting

If you find a security concern, broken access control, misleading content, or a document mismatch, report it privately with enough detail to reproduce the issue. Do not include passwords, access tokens, or unnecessary personal data in the report.

08Security is an ongoing process

No website can promise absolute security or uninterrupted availability. We review the Knowledge code and content as the site changes, and we update published notices when a material change affects users.
